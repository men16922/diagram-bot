# Diagram Bot — AWS 자동 구성도 개선 계획

- 작성일: 2026-10-17
- 상태: 계획 작성 완료. 아래 P1~P5 구현은 아직 시작하지 않았다.
- 목표: 기존 AWS SSO로 조회한 설정을 자동 배치하고, 편집 가능한 `.drawio`와 PNG로 출력하는 시연 버전.
- 현재 작업 기준: 이 문서. 기존 `PLAN.md`의 제품 확장안보다 이번 범위와 단계가 우선한다.

## 1. 확정 범위

- 로컬 앱, AWS 한 계정·한 리전. 계정 안에서는 여러 VPC를 구분한다.
- 기존 SSO 프로파일과 boto3 인증 체인을 사용한다. Resource Explorer와 DevOps Agent를 호출하지 않는다.
- 대상: VPC, Subnet, EC2, ELBv2, TargetGroup, 등록 대상. ALB 중심으로 시연하고 기존 NLB 지원을 보존한다.
- SG·ENI·EBS는 기존 API에서 확인한 참조만 제공한다. 상세 수집은 이번 범위에 추가하지 않는다.
- API로 확인한 포함·배치·연결·등록 관계만 표현한다. LLM 관계 추론이나 실제 통신 분석을 넣지 않는다.
- FastAPI + boto3 + 현재 JavaScript 화면 + 로컬 draw.io 편집기를 유지한다. React/DB 전환은 하지 않는다.
- AWS 계정에 검색 서비스, 수집 에이전트, CloudFormation 스택을 설치하지 않는다.
- RDS/EKS, 라우팅, Listener/Rule, 변경 비교, 예약 수집, 다중 계정은 후속 범위다.

## 2. 기존 구현과 이번 변경

| 영역 | 현재 코드에서 확인한 상태 | 이번 작업 |
| --- | --- | --- |
| 수집 | `collector.py`: STS 계정 확인, EC2/ELBv2 조회, 페이지네이션, 부분 실패 보존 | 재사용. 인증·계정·조회 오류 표시와 필요한 권한 안내 점검 |
| 관계 | `graph.py`: ID 기반 조인, API 필드 근거, 참조 노드 | 안정적인 관계 ID 및 보기용 데이터 계약 보강 |
| 배치 | `drawio.py`: VPC/AZ/서브넷 그룹, 고정 열·행 좌표와 일부 선 경로 | 배치 계산과 XML 생성을 분리하고 계층형 자동 배치 개선 |
| 화면 | VPC 전환, 검색·목록, 속성·근거 패널, 참조 표시 | 전체 구성·상세 구성·선택 리소스 보기와 연결 강조 |
| 문서 | 로컬 draw.io, 편집본 저장, revision 검사, `.drawio`·PNG | 보기별 문서 분리, 재배치 시 편집본 보존, 출력 일치 검증 |
| 검증 | 기존 시연 자료 및 24개 pytest 통과 기록 | 변경 후 회귀 검사와 새로운 보기·배치·출력 시나리오 검증 |

기존 통과 기록은 이번 변경의 검증 결과가 아니다. 실제 AWS SSO 수집도 아직 검증되지 않았다.

## 3. 처리 구조

```text
SSO 프로파일 → STS 계정 확인 → EC2/ELBv2 읽기 API
                                    ↓
                       Snapshot(raw + coverage + 시각)
                                    ↓
                         Resource / Relation 그래프
                                    ↓
                    보기 선택 → 표시 그래프 / 그룹 구성
                                    ↓
                  자동 배치 → 도형 좌표 / 그룹 크기 / 선 경로
                                    ↓
                   draw.io XML → 편집·저장 → .drawio / PNG
```

JSON/CSV는 동일 Snapshot에서 생성한다. 화면 필터 때문에 원본 인벤토리가 변하지 않게 한다.

### 관계와 표시 계약

- Resource: 안정적 ID, 종류, 계정·리전, 원본 속성, 직접 조회/참조만 확인 상태.
- Relation: 안정적 ID, source/target, 관계 종류, API·필드 근거, 포트·AZ 등의 한정자.
- 관계 ID는 원본 배열 순서나 변동하는 health 상태에 의존하지 않는다. 같은 대상의 서로 다른 포트 등록은 구분한다.
- 기존 스냅샷과 저장된 XML을 계속 읽는다. 새 `relationId`를 추가할 때 기존 `relationIndex` 문서의 선택 연동도 지원한다.
- 포함 관계는 그룹으로 표현한다. EC2는 API가 확인한 서브넷 안에 배치한다.
- 다중 서브넷 ALB는 VPC 수준에 한 번 표시한다. 연결된 서브넷은 선택 시 배치 관계로 보여준다.
- TargetGroup은 논리적 자원으로 표시하며 임의로 특정 서브넷에 넣지 않는다.
- IP 대상은 별도 대상으로 유지하고 같은 IP의 EC2에 추측으로 합치지 않는다.
- 조회하지 못한 대상은 참조 상태로 남긴다. 권한 실패를 빈 환경으로 표시하지 않는다.
- 선의 의미는 등록·연결·배치다. 트래픽 방향이나 실제 통신 성공을 암시하지 않는다.

## 4. 화면과 배치

| 보기 | 표시 내용 | 동작 |
| --- | --- | --- |
| 전체 구성 | 계정·리전·VPC 경계와 주요 리소스 수 | VPC를 선택하면 상세 보기로 이동. 요약 도형은 실제 자원과 구분 |
| 상세 구성 | 선택 VPC의 AZ·서브넷·EC2·ALB·대상 그룹 | 기본 설정 관계 표시. SG/ENI/EBS 참조는 선택 옵션 |
| 선택 리소스 | 선택 자원과 직접 연결된 자원·필요한 상위 경계 | 관계 유형·근거 확인. 원래 상세 보기로 복귀 |

검색/종류 필터와 캔버스의 적용 범위를 명확하게 표시한다. 표시된 자원 수와 전체 수집 수를 구분한다.

자동 배치는 ALB·대상 그룹·대상 순서를 읽기 쉽게 정렬하고, AZ/서브넷 경계를 보존한다.
동일 입력·보기 옵션·배치 버전은 동일 좌표를 생성하도록 정렬과 옵션을 고정한다.
긴 라벨을 위한 공간을 확보하고, 라벨을 줄일 경우 전체 이름은 속성 패널에서 제공한다.

ELK layered를 첫 후보로 작은 검증을 수행한다. 중첩 그룹·경계를 넘는 선·오프라인 실행을 검증한다.
채택 시 고정 버전의 브라우저용 자산과 Worker를 로컬에 포함하고 라이선스·체크섬을 기록한다.
현재 Python/CLI 배포에 Node 실행 환경을 필수로 추가하지 않는다. 서버/CLI 기본 배치 경로는 유지하며
실제 문서에 사용한 배치 방식·버전을 기록한다. ELK가 통합 조건을 충족하지 못하면 기존 배치를
계층별로 개선하는 대안을 사용하고 실험 결과와 선택 이유를 문서화한다.

자동 재배치는 초기 생성 또는 사용자의 명시적 실행에만 적용한다. 사용자가 수정한 문서를
보기 전환만으로 덮어쓰지 않는다. 재배치 전 편집본을 보존하고 새 revision으로 결과를 저장한다.
문서 키에 Snapshot·보기 종류·VPC·선택 리소스·참조 옵션을 포함해 서로 다른 보기를 격리한다.

## 5. 실행 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| P1. 그래프 계약·샘플 | 관계 ID, 보기용 그래프 분리, 기존 문서 호환, 경계 사례 fixture | 입력 순서를 바꿔도 동일 ID. 포트별 등록 구분. 미조회 참조·다중 서브넷 ALB·IP 대상 관계가 정확함 |
| P2. 배치 분리·개선 | layout 결과와 XML 직렬화 분리, ELK 검증 후 적용 또는 기존 배치 개선 | 중첩 경계 유지, 도형 겹침·잘림 없음, 동일 입력 재현. 오프라인에서 배치 가능. 배치 선택 근거 기록 |
| P3. 보기·탐색 | 전체/상세/선택 보기, 직접 관계 강조, 근거 패널 연동 | 모든 보기 전환이 동작하고 선택과 패널이 일치. 집계 수·숨김 수·부분 조회 상태 구분 |
| P4. 편집·출력 | 보기별 저장, 재배치와 수정본 보존, 동일 문서에서 draw.io/PNG 생성 | 수정한 위치·주석이 두 형식에 일치. 재열기·한글·AWS 아이콘·PNG 1/2/3배·투명 배경 확인 |
| P5. 시연 마감 | 샘플 실행, 문서·권한 안내, 회귀·브라우저 검사, 산출물 정리 | AWS 인증 없이 아래 시연 시나리오 재현. 실제 SSO 검증 여부를 별도로 명시 |

순서: P1 → P2 → P3 → P4 → P5. 첫 구현 단위는 P1이며 프레임워크 교체나 서비스 범위 확장은 하지 않는다.

### 검증 기준

- 각 변경에 필요한 관계·배치·문서 회귀 검사를 추가하고 `make check`를 수행한다.
- 브라우저에서 보기 전환 → 선택 → 속성 확인 → 위치·주석 편집 → 저장 → `.drawio`·PNG 다운로드를 검증한다.
- 샘플: 2 VPC, 복수 AZ, 다중 서브넷 ALB, 다중 대상 그룹, 같은 EC2의 여러 포트 등록,
  IP 대상, 미조회 참조, 긴 한글 이름, 빈 환경, 부분 조회 실패를 포함한다.
- 고정 샘플에서 의도한 그룹 포함을 제외한 도형 겹침과 경계 밖 잘림이 없어야 한다.
  PNG와 편집 화면을 육안 검토하고 복잡한 관계선의 가독성도 확인한다.
- 별도 100개 리소스 fixture의 배치 시간을 기록한다. 시연 장비에서 5초 이내를 목표로 하되
  측정 전 성능 달성이나 대규모 환경 지원을 주장하지 않는다.
- 실제 SSO 검증은 자격증명과 네트워크가 사용 가능할 때 한 계정·한 리전에서 수행한다.
  주요 자원과 관계를 AWS API/콘솔과 대조한다. 불가능하면 샘플 시연 완료와 실계정 검증 미완료를 분리한다.

## 6. 최종 시연·산출물

1. 샘플 전체 구성에서 VPC를 선택한다.
2. ALB를 선택해 대상 그룹·등록 대상과 API 근거를 확인한다.
3. 상세 보기에서 EC2의 AZ/서브넷 위치를 확인한다.
4. 부분 조회·참조만 확인한 리소스를 표시한다.
5. 위치를 조정하고 검토 메모를 넣어 저장한다.
6. `.drawio`를 다시 열고, 동일 편집본의 PNG 및 같은 Snapshot의 CSV/JSON을 확인한다.

제공물: 실행 가능한 로컬 앱, 합성 샘플 Snapshot, 편집 가능한 `.drawio`, PNG,
CSV/JSON, 화면 캡처, 재현 절차, 검증 결과. 합성 샘플에는 SAMPLE 표시를 유지한다.

## 7. 참고 범위

DevOps Agent의 계층별 보기와 관계 탐색을 제품 참고로 사용한다. 내부 구현이나 동일한
레이아웃 알고리즘을 안다고 가정하지 않는다. 우리 전체/상세/선택 보기는 독립 설계이며
DevOps Agent의 CloudFormation Container 보기나 학습 기반 Topology를 그대로 구현하지 않는다.
