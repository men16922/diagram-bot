# 오케스트레이터 (GPT-6.1 Sol)

- 붙여넣을 한 줄: `<DB>/docs/porting/ORCHESTRATOR.md를 읽고 그대로 수행하라. 회사 저장소=<경로>, DB=<경로>, 목표 Level=<N>, 프런트=<예|아니오>, 회사 값: <회사:…> 목록`
- effort medium. 상한 $3(예비비에서), 세션당 컨텍스트 150K.

## 읽을 것
- `docs/porting/README.md` 카드 표, `docs/porting/RULES.md`, 이 파일.
- `PORTING_LOG.md`의 각 보고 절. 서브에이전트 대화록·전체 로그·카드 본문은 읽지 않는다.

## 순서
- T0 → T1 → S → T2 → S → T3 → S → T4 → S → T5 → S → T6 → 끝.
- 목표 Level 위 카드는 건너뛴다. T5는 프런트=예일 때만.

## 셸 단계 (네가 직접, 출력은 항상 `2>&1 | tail -40`)
- T0: 카드 `docs/porting/T0-copy.md`의 명령 그대로.
- S: `<회사:전체 테스트 명령> 2>&1 | tail -40`. 실패 꼬리는 다음 카드 프롬프트에 붙인다.
- T5 전 S: `PYTHONPATH=<DB>/src python -c "from diagram_bot.editor import install_editor; print(install_editor(destination='<회사:정적 경로>/editor'))"` 후 `<회사:프런트 빌드 명령> 2>&1 | tail -40`.

## 카드 실행
- 카드마다 서브에이전트 1개(도구의 서브에이전트/태스크 기능, 모델은 표의 담당). 동시에 하나만.
- 프롬프트 = README의 카드 한 줄 + 직전 보고의 「다음 카드에 넘길 것」 + 필요한 `<회사:…>` 값.
- 보고를 받으면 카드의 완료 조건 명령을 직접 다시 돌려 exit code를 확인한다(`| tail -20`). 보고만 믿지 않는다.
- `결과: 이어서`: 같은 카드에 새 서브에이전트, 그 보고 절만 넘긴다(재시도 아님, 카드 상한 안).
- 실패: 카드당 재시도 1회. 같은 카드가 이어서를 2번 넘기면 카드를 하위 카드로 나누자고 사람에게 제안하고 멈춘다.

## 예산
- 보고의 비용과 네 비용을 누적한다. 카드 상한에 닿으면 그 카드 중단. 누적 $100 전에 멈춘다.
