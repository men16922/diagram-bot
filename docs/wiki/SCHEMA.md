# 위키 작성 규칙

> 한 페이지에 한 주제. 모든 사실은 코드 경로로 근거를 단다. 페이지를 바꾸면 `index.md`와 `log.md`도 바꾼다.

## 페이지 형식

```markdown
---
title: 사람이 읽는 제목
summary: 한 문장 요약 (index.md와 llms.txt에 그대로 쓰인다)
sources: [src/diagram_bot/모듈.py, tests/test_모듈.py]   # 이 페이지의 근거 파일
related: [다른-페이지-이름, ...]                          # 확장자 없는 파일 이름
updated: YYYY-MM-DD
---
# 제목

> 한두 문장 요약.

## 핵심
- 사실 위주의 짧은 항목. 함수·클래스·필드 이름은 `코드`로, 위치는 `src/diagram_bot/x.py`의 함수 이름으로.

## (주제별 절)

## 바꿀 때 주의
- 이 영역을 고칠 때 깨지기 쉬운 불변식과 함께 고쳐야 하는 테스트.

## 관련
- [[다른-페이지]] — 왜 관련 있는지 한 줄.
```

## 규칙

1. **근거 우선.** 코드에서 확인한 것만 쓴다. 확인하지 못한 동작은 쓰지 않거나 `확인 필요`로 표시한다. 줄 번호는 바뀌므로 쓰지 않고 함수·클래스 이름으로 가리킨다.
2. **한 주제 한 페이지.** 길어지면 나눈다(대략 250줄 이하). 같은 내용을 두 페이지에 쓰지 말고 링크한다.
3. **링크는 `[[페이지-이름]]`** (파일 이름에서 `.md`를 뺀 것). 일반 Markdown 뷰어용으로 같은 줄에 `(페이지-이름.md)` 상대 링크를 함께 써도 된다.
4. **문체.** 한국어 서술, 코드 식별자·API 경로·AWS 서비스 이름은 원문. 표는 목록이 3열 이상일 때만.
5. **갱신.** 페이지를 추가·삭제·이름 변경하면 [[index]]의 목록, 루트 `llms.txt`, [[log]]에 한 줄을 남긴다. 코드를 바꾼 PR은 관련 페이지의 `updated`와 내용을 함께 고친다.
6. **비밀 금지.** 계정 ID·키·토큰·내부 URL은 예시 값(`111122223333`, `d-1234567890`)만 쓴다.
